## Часть 2: Спецификация проекта

### 2.1 Обзор и стек
**Проект:** HighLoad маркетплейс (Spring Boot 4.1, Java 25, Виртуальные потоки)
**БД:** PostgreSQL (Liquibase), Redis (Pub/Sub), S3 (MinIO).
**Архитектура:** Модульный монолит (ArchUnit контроль). Аутентификация: Keycloak (JWT).

### 2.2 Архитектурные принципы
- **Package-by-Feature (Пакетная структура)** — базовый пакет `dn.marketplace`. Домены изолированы (`account`, `order`, `product`).
- **Внутренняя иерархия домена:**
    - `api/` (внешние контракты: `controller` и `dto` — выступают портами)
    - `entity/` (сущности БД; public — изоляцию держит ArchUnit, решение №9)
    - `repository/` (Spring Data; public, наружу домен смотрит через `*Facade`)
    - `service/` (бизнес-логика; публичный `*Facade` лежит в корне пакета домена)
- **Синхронизация БД:** Скрипты Liquibase изолированы по доменам. Триггеры и бизнес-проверки (`CHECK`) реализуются на стороне БД.
- **Работа со временем:** Строгое использование `java.time.Instant` для всех системных дат, избегая иллюзии локальных таймзон.
- **Единый источник правды (SSOT):** Keycloak — авторитет для аутентификации. В БД маркетплейса хранятся только Read-Only проекции (`email_snapshot`), обновляемые асинхронно через события (Eventual Consistency).
- **Синхронно/Асинхронно:** `@Transactional` для ядра бизнес-логики. Transactional Outbox (`SKIP LOCKED`) для фоновых задач.
