# VPS под агентский цикл

## Сколько машин: одна

Агенты не демоны. `claude` и `codex` — обычные CLI, которые раннер вызывает на время
одного джоба и убивает. Ничего постоянно работающего на машине нет, поэтому вопрос
«отдельный сервер под каждого агента» не стоит: им не нужно даже по процессу.

Две машины были бы строго хуже: два пула раннеров, две авторизации и CI, который не
может переиспользовать кеш Gradle между компиляцией и ревью.

## Размер

| Параметр | Минимум | Комфортно |
| --- | --- | --- |
| RAM | 8 GB при одном раннере | 16 GB при двух |
| vCPU | 4 | 4–8 |
| Диск | 40 GB | 80 GB |

Формула в скрипте: `4 + 4 × количество раннеров` гигабайт. Gradle с `-Xmx3g` плюс
контейнеры Postgres и Redis занимают это целиком. Swap включается скриптом — без него
OOM-killer убивает Gradle посреди прогона, и это выглядит как случайно падающий тест.

**Один раннер выполняет ровно один джоб за раз.** Параллелизм даёт не вторая машина,
а второй экземпляр раннера: отдельный каталог, отдельный systemd-сервис. GitHub сам
раскидает джобы по свободным. Двух достаточно.

## Порядок

```bash
# 1. На машине, где ты залогинен в gh с правами админа репозитория:
gh api -X POST repos/devDaniilNovikov/Marketplace/actions/runners/registration-token --jq .token

# 2. На VPS от root (токен живёт один час):
REPO=devDaniilNovikov/Marketplace \
RUNNER_COUNT=2 \
RUNNER_TOKEN=<токен из шага 1> \
./vps-bootstrap.sh

# 3. Авторизовать Codex (единственный шаг, который нельзя автоматизировать):
sudo -u ghrunner -H codex login --device-auth

# 4. Проверить:
./vps-verify.sh
```

Скрипт идемпотентен: повторный запуск доводит состояние, а не ломает.

## Авторизация подписок

**Codex.** `codex login --device-auth` печатает короткий код, подтверждаешь его с
телефона — браузер на сервере не нужен. Если команда упирается в запрет, включи
device-code вход в настройках безопасности аккаунта ChatGPT.
Запасной путь: залогиниться на ноутбуке и скопировать `~/.codex/auth.json` на сервер
в `/home/ghrunner/.codex/auth.json` — файл не привязан к хосту. Дальше `chown` и `chmod 600`.

**Claude.** На сервере делать нечего: токен приезжает из секрета репозитория
`CLAUDE_CODE_OAUTH_TOKEN` прямо в окружение джоба. Протух — на ноутбуке
`claude setup-token`, обновить секрет. Токен живёт около года и расходует лимиты
подписки, а не выставляет отдельный счёт API.

## Переключение цикла на свою машину

Одна переменная репозитория:

    AGENT_RUNS_ON = self-hosted

Она подставляется в `runs-on` всех десяти джобов цикла. Не задана — работаем на
раннерах GitHub. Откат — удалить переменную; править workflow не нужно.

`claude.yml` и `claude-code-review.yml` намеренно остались прибиты к `ubuntu-latest`:
аварийный вход `@claude` не должен зависеть от машины, которая может лежать.

## Что переезд даёт

- Минуты Actions перестают тратиться. Это снимает главную цену перевода репозитория
  в private.
- Кеш Gradle и образы Testcontainers живут между прогонами: `full` падает с ~9 минут
  до ~2. На цикле из трёх раундов это разница между 45 и 15 минутами на задачу.
- Обе подписки работают напрямую, `OPENAI_API_KEY` не нужен вообще.

## Безопасность

**Только приватный репозиторий.** На публичном PR из форка выполнит произвольный код
на этой машине — с твоими подписками и токеном репозитория в окружении. Это не
теоретический риск, а прямое предупреждение в документации GitHub.

**Группа `docker` = root на хосте.** Testcontainers требуют доступ к демону, обойти
это нельзя. На машине, которая больше ничего не делает, размен приемлемый. Путь
ужесточения — rootless Docker: демон работает от `ghrunner`, эскалации нет, но
Testcontainers придётся указать сокет через `DOCKER_HOST` в `.env` раннера.

**Пользователь без sudo** — намеренно. На этой машине лежат обе подписки и токен
с правом записи в репозиторий.

Чего скрипт не делает и что стоит сделать самому: закрыть входящие порты кроме SSH,
отключить парольный вход по SSH, включить автообновления безопасности.

## Отладка

| Симптом | Куда смотреть |
| --- | --- |
| Джоб висит в очереди | `systemctl list-units 'actions.runner.*'` — все ли active |
| `gh: command not found` в джобе | `gh` ставится скриптом; на `ubuntu-latest` он был предустановлен |
| Testcontainers не стартуют | `sudo -u ghrunner -H docker info` — видит ли пользователь демон |
| Codex просит логин | `ls -l /home/ghrunner/.codex/auth.json`, владелец и права |
| Тесты падают без причины | `dmesg | grep -i oom` — почти всегда не хватило памяти |
